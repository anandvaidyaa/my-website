The problem

Three carrier portals, twenty minutes, every shipment.

Dispatch teams were spending hours creating shipping labels and tracking packages by hand across separate FedEx, DHL and UPS portals. It was a twenty-minute manual process, and it held back shipping SLA compliance.

02

Architecture

One front door for every carrier.

I built a centralised, secure API gateway on Azure API Management, protected with OAuth 2.0, that automates the carrier integrations: label generation goes through the gateway, and tracking updates arrive as live webhooks instead of someone checking each portal.

  1. Step 1

    One entry point

    Dispatch systems integrate once, with the gateway, instead of three times with three carriers.

  2. Step 2

    Authenticate at the edge

    Callers present OAuth 2.0 tokens (Azure AD B2C), validated at the gateway before a request reaches any carrier. Carrier API keys stay out of client applications.

  3. Step 3

    Route and automate labels

    Throttling, versioning and logging live in one place; each carrier integration only contains carrier-specific logic, and label generation is automated.

  4. Step 4

    Track with webhooks

    Carriers push status changes as they happen, so tracking stays current without polling or portal checks.

04

Engineering decisions

Put the hard parts at the gateway.

D1

A gateway in front of every carrier

API Management centralises cross-cutting concerns — token validation, throttling, versioning and logging — so each carrier integration only contains carrier-specific logic.

Trade-off: the gateway becomes a critical dependency, so its tier, scaling and availability have to be planned like any production service.

D2

OAuth 2.0 tokens instead of shared credentials

Callers authenticate with short-lived tokens validated at the gateway, which keeps carrier API keys out of client applications.

Trade-off: token issuance and app registrations add setup, and expiring tokens must be handled gracefully by every client.

D3

Webhooks for tracking instead of polling

Carriers push status changes as they happen, so tracking stays current without repeatedly querying each carrier.

Trade-off: webhook endpoints must verify senders and cope with retries and duplicate events.
